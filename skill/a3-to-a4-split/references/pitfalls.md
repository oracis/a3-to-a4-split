# 踩坑记录

这份文件记录实现过程中真实踩过的坑，遇到异常时先来这里对照。

## 1. 为什么不能直接切 Word

`.docx` 里不存在「页」这个对象，只有段落和浮动对象，**分页是 Word 排版引擎算出来的**。
这类试卷又是用绝对定位文本框拼版（左半 A4 从 84.6pt 开始、右半从 624pt 开始），
文件里没有「第 2 页从哪开始」的信息。

所以：

- 改纸张为 A4、或改分栏 → Word 重新排版，文本框整体错位，是事故不是切分；
- 浏览器纯前端也不可能做到——没有 Word 排版引擎。

必须先让 Word 排一次版（导出 PDF），再按实际渲染结果下刀。`split_word.py` 自动完成这一步。

## 2. 删 docx 里的浮动对象会让后面的页塌掉

曾试图从 `word/document.xml` 删掉左侧「班级学号式 / 考场座次」两块 `wp:anchor`
（各 35.2×697.5pt）来去掉姓名学号栏。删除本身成功，但 Word 重排后**第 2 张 A3 的内容整体塌了**。

结论：要去掉页边元素，在 **PDF 层裁剪**，不要动 docx。
`split_a3.py` 的 `detect_margin_strip()` 会识别「窄而高、右边界落在正文框左侧之外」的图片
（10 < w < 90、300 < h < 820），把左页裁剪框推到它右侧 +2pt。

## 3. 按页面中线切会丢字

A3 宽 1190.64pt，中线 595.32pt。但两栏内容框常常不对称：

| | 左栏 | 右栏 |
|---|---|---|
| A3 #1 | 84.65 ~ 619.35 | 624.10 ~ 1167.00 |
| A3 #2 | 36.80 ~ 617.20 | 622.00 ~ 1171.70 |

中线右侧 23~24pt 属于左页。按中线切，左页最后 1~2 个字被切到右页，
句子读起来就缺字或变义（`多少千克？` → `多少克？`）。

正确切口 = 左栏右边框与右栏左边框的中点（本例 621.8 / 619.6）。

## 4. 平移与裁剪的顺序不能反

要让新页面落在 `[0, 0, 595.32, H]`，内容需要整体左移 `wl`。
写成了：

```
q  0 -60 ... re W n  1 0 0 1 -wl 0 cm  <原内容>  Q     ← 错
q  1 0 0 1 -wl 0 cm  0 -60 ... re W n  <原内容>  Q     ← 对
```

前者裁剪框还钉在旧坐标系上，内容左移后就落到裁剪框左边外面，**左侧整条边框被裁掉**。
现象很有辨识度：页面左边框线消失、内容看起来「偏右且被切」。

## 5. 页面框原点非零会让打印缩放错

第一版输出的 4 页 MediaBox 分别是 `[54.34 0 649.66 842.04]`、`[595.32 0 1190.64 842.04]`、
`[29.36 …]`、`[595.32 …]`。PDF 规范里纸张尺寸按宽×高算，但部分阅读器和打印驱动
直接取右上角坐标当尺寸，会认成 649.66 宽而不是 595.32，打印被缩放或裁边。

统一写成 `[0 0 595.32 842.04]`、内容平移回原点。`check_pdf.py` 会校验这两点。

## 6. 「灰底 + 发虚 + 重影」的两个来源

逐步排除后才定位清楚，**不是转换掉画质，也不是切分造成的**：

- **源 Word 的网点底纹**：`word/document.xml` 里有 64 处 `<w:shd w:val="pct10">`。
  10% 网点在屏幕缩放时与笔画混叠，就是浅灰底框。→ `clean_shading.py` 删除。
- **公式位图的透明蒙版**：文档里没有原生公式（`m:oMath = 0`），38 个分数/算式是 MathType
  OLE 对象，导出 PDF 时变成「RGB 位图 + 灰度软蒙版 SMask」共 9 对。
  低分辨率预览做 alpha 合成时在笔画外产生灰色光晕。→ `flatten_smask.py` 预合成到白底。

验证方法：把位图按 `rgb*a + 255*(1-a)` 合成到白底后直接看，是清晰的实心黑字；
说明位图本身没问题，问题在合成/渲染环节。不带蒙版的纯数字算式（`1.8×20=`）从一开始就是清晰的。

## 7. 页顶黑色实心小方块

原文自带的**装订/裁切标记**，8 个 28.2 × 14.15pt 黑色填充矩形
（每张 A3 顶部 4 个，x ≈ 25.8 / 570.6 / 620.4 / 1120.1，A3#1 y=797.99、A3#2 y=807.59）。

绘制形式：`<x> <y> 28.2 14.15 re f*` 与同矩形 `re S`，外面套 `/P <</MCID n>> BDC … EMC`。

删除要点：
- 只删「填充 + 描边」这两条绘图指令，**保留 BDC/EMC 配对**，否则标记内容结构不平衡；
- 判据加一条「不被任何一栏内容框完整包含」——标记画在页边空白处，
  而正文里的题号框、答题格是**描边**不是填充，且落在内容框内，因此不会误删；
- 注意不能只按 x 判断：`x=570.6` 那个标记在左栏 x 范围（84.65~619.35）之内，只能靠 y 区分。

## 8. PowerPoint / PowerShell 的编码

用 Python 写 `.ps1` 给 Windows PowerShell 5.1 执行时，必须用 `encoding='utf-8-sig'`（带 BOM），
否则 PS 按 ANSI 解码，中文路径变乱码，`Documents.Open` 直接失败。

## 9. PDF 增量更新的几个细节

- xref 的 subsection 必须按对象号升序排列；
- `/Prev` 指向原文件最后一次 `startxref`，`/Size` 要 ≥ 新对象号 + 1；
- `/Root`、`/Info`、`/ID` 从原 trailer 继承，漏了 `/Root` 阅读器直接打不开；
- `/Length` 必须等于压缩后字节数，否则部分阅读器截断内容；
- 同一个对象号在文件里出现两次时，**最后一次**生效（增量更新的原理）。

`check_pdf.py` 就是围绕这几条写的，改完务必跑一遍。

## 10. 渲染验收不要用 headless 的 virtual-time

`chrome --headless --virtual-time-budget` 会冻结 Worker，pdf.js 永远不返回，
截图是空白页；`--dump-dom` 同理。用 CDP（`--remote-debugging-port` + WebSocket）
做真实等待才可靠，这也是 `render_pages.mjs` 的做法。

另外 `chrome --headless --screenshot 文件.pdf` 也不行——无头模式不加载 PDF 插件。

## 11. 这台机器上的环境限制（同类环境可参考）

- `Add-Type`（PowerShell 调 .NET / WinRT `Windows.Data.Pdf`）被安全策略禁止；
- `pip install pymupdf / pypdf` 拉不到包（pypi 与清华镜像都不通）；
- 因此 PDF 处理全部用**标准库手写**（`re` + `zlib`），渲染验收走 Node + CDP + pdf.js。

这些限制反而促成了「零依赖」的实现，换个环境也是可用的。
